# Production configuration — not deployed

The standalone production file is an implementation candidate. Its static frontend image was built and its non-root Nginx config validated locally. The full TLS/MySQL/worker production stack has not been deployed or tested with institutional data. Identity hardening and operational approvals in the security backlog remain release gates.

Copy `.env.production.example` to `.env.production`, configure unique random secrets, actual host/origins and an approved TLS_DIRECTORY containing `fullchain.pem` and `privkey.pem`. Never use the demonstration identities or production secrets in shared development. Use `docker compose --env-file .env.production -f docker-compose.prod.yml config --quiet` to validate without printing expanded secrets.

After approved backup and release review, authorized IT staff can build images and start with `docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build`. This is an instruction for a future authorized deployment, not a record that it occurred. Migration/collectstatic runs once in the migration service; workers and Gunicorn wait for successful completion. Do not scale migration or Beat. Schedule migrations under an operational release lock if multiple deployers are possible.

Only Nginx exposes 80/443. MySQL, Redis, Gunicorn and static frontend are internal. Nginx overwrites forwarded TLS headers, Django trusts them only with TRUST_PROXY_TLS, and app services have no published ports. Gunicorn serves API, Nginx serves static assets, private media is accessible only through authenticated download endpoints. Renew certificates using the university-approved strategy; certificate automation is not bundled. Restrict `/admin/` additionally at the network/identity layer. Swagger currently loads its UI assets from configured defaults; the strict production CSP may require self-hosted Swagger assets before enabling it publicly.

Define CPU/memory limits from measured workload (not invented capacity figures), encrypted persistent storage, scheduled off-site backups, health alerts and recovery drills. Liveness `/api/v1/health/live/`, readiness `/api/v1/health/ready/`, restricted component health `/api/v1/manage/health/`. Forward structured process/access logs to approved monitoring; correlation response headers exist but end-to-end correlation and structured JSON logging remain incomplete. Container vulnerability scanning and real load/accessibility assessment remain required.

Initial administrator: run `createsuperuser` interactively in the backend container. No default production administrator is created. Establish administrator MFA/reauthentication before enrollment; these controls are not implemented in this milestone. External SSO/mail/SMS/push, certificate credentials and real student-system endpoints are absent and disabled by absence of adapters. Never invent them.
