# BNUT UI/UX milestone

Persian-first, `lang=fa`, document-level RTL, Vazirmatn 5.3.0 bundled via Fontsource (SIL Open Font License distributed in package), navy `#142e4c` identity and white/neutral surfaces. Branding is provisional and configurable; no official university logo is used. `frontend/src/bnut.css` overrides preserved base styles; reusable UI components implement fields, feedback/error/loading/empty states, status badges and pagination. Product dates use Persian presentation and Tehran time. Tracking IDs/emails use explicit LTR where needed; further mixed-direction review remains backlog.

Public layout: institutional navigation, answer-first search, process explanation, help article cards, directory, announcements and support hours. Student layout: attention dashboard, guided request form, conversation, attachments, resolution confirmation, feedback, profile/security and notifications. Staff layout adds assigned/scoped inbox, internal notes, claim/release/transfer and state controls. Managers see authorized workloads/response metrics; administrators see operational overview and resource editors/form builder/settings/audit/service health. Some configuration fields currently use numeric related IDs rather than searchable selectors; this is functional but remains a usability limitation.

Reviewable artifacts: existing `wireframes.html` is the original low-fidelity prototype and is retained as history; current runnable React routes and browser screenshots in ignored `artifacts/` show this milestone. No Figma link or complete accessibility certification is claimed. New screens were described in source/task planning before coding; a consolidated updated wireframe set remains follow-up work.

User flows: guest search -> article/FAQ -> public department -> authenticated student -> four-stage request wizard -> tracking/conversation; staff scoped inbox -> claim -> public reply or internal note -> request information -> resolve with summary; student confirmation -> feedback or justified reopening; manager dashboard -> department queue; administrator -> configure department/category/form/content/calendar -> preview/commit import -> distribute activation through an approved external mechanism.

Labels, visible keyboard focus, skip links, semantic forms/tables, details/summary FAQs and text status indicators are implemented. Tested mobile viewport: 390×844 public help flow without horizontal overflow. Full WCAG 2.2 AA audit, staff/admin mobile workflows, accessible charting and multi-browser testing are pending. Mutations use pending/disabled feedback and display errors; ErrorBoundary offers recovery on render failures. No color-only status communication or placeholder action controls are intended.
