# Test strategy

Run backend checks in Docker against actual MySQL 8.0; the test suite asserts server version and never substitutes SQLite. Authentication tests include CSRF/login/session/logout/deactivated accounts/role safety; domain tests cover ownership, department scope, confidential admin denial, internal-note separation, guarded state transitions, competing claim conflicts, transfer privacy, attachments and policy-controlled priority. Portal tests cover normalized Persian search/publication, admin hierarchy validation/metadata, forms/snapshots, working hours/holidays, activation token reuse, CSV preview/duplicates/idempotence and scheduled escalation/closure.

Vitest/Testing Library checks API errors/CSRF, session cache switching, Persian login field behavior and conditional required dynamic inputs. Chromium E2E uses only explicitly seeded synthetic identities through real Compose frontend/API/MySQL services: guest mobile help -> article/FAQ; student wizard/upload -> employee claim/internal note/public reply -> student reply -> resolution/confirmation/feedback -> denied other-student ticket/file; React administrator department/category creation; manager metrics. Browser results remain ignored artifacts, not real student data.

ESLint/Prettier and Ruff cover code checks. npm audit and pip-audit scan dependency advisories; they are not an application security certification. GitHub Actions repeats container-based integration/MySQL/browser checks and separate Python lint/audit. Hosted success is reported only after observing it. Production frontend image and config are validated locally. Full TLS deployment, restore drills, concurrent race stress, exhaustive RBAC combinations, all 15 separate requested E2E scenarios, accessibility/load/cross-browser testing and full operational recovery remain follow-up work.
